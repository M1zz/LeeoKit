# 버그 신고 분류: 무엇을 받고, 어떻게 읽어서 고치는가

버그 신고를 고르면 사용자는 먼저 **어떤 문제인지**를 고른다(`LeeoBugCategory`).
분류마다 묻는 칸, 부탁하는 사진, 묻지 않고 붙이는 진단(`LeeoBugProbe`)이 다르다.
이 문서는 받는 쪽, 즉 개발자가 신고 한 건을 열었을 때 **무엇을 보고 어떻게 판정하는지**를 적는다.

## 신고 한 건의 모양

`message` (사용자가 쓴 글)

```
문제 종류
결제 · 구매 복원

무엇을 샀고, 지금 어떻게 보이나요?
평생 이용권을 샀는데 다시 깔고 나니 잠겨 있어요.
```

`deviceInfo` (자동 첨부, 보내기 전에 사용자에게 그대로 보인다)

```
App 5.1.9 (26) | iPhone17,2 | iOS 26.1        ← 늘 붙는 첫 줄
pro=false trial=expired                       ← 앱이 준 extraInfo / categoryInfo
category: purchase                            ← 분류 (번역하지 않음, 허브가 이 글자로 거른다)
[purchases] owned=none
[purchases] revoked=none
[appReceipt] firstDownload=2026-09-03 firstBuild=17 env=Production
[storefront] country=THA canPay=on
```

사진은 `screenshot1~3` 에 온다(앱이 `acceptsScreenshots` 를 켠 경우만).

> 진단 한 줄이 `timeout` 이면 3초 안에 답이 없었던 것이다. 그 값은 **모르는 것**이지 비어 있는 것이 아니다.

---

## 1. 꺼지거나 열리지 않아요 (`crash`)

| 묻는 것 | 부탁하는 사진 | 자동 진단 |
| --- | --- | --- |
| 언제 무엇을 하다가 · 어떻게 되나요 · 매번 그런가요 | 멈추거나 꺼지기 직전 화면 (흰 화면이어도) | `[device]` |

먼저 알림: **앱을 지우기 전에 보내 달라**고 말한다. 지우면 기기에만 있던 데이터와 진단 기록이 같이 사라진다.

**읽는 법**
1. 첫 줄의 버전 · 빌드로 그 빌드의 크래시 리포트(허브 진단 탭, `LeeoDiagnostics`)를 같은 기종으로 거른다. 같은 날 같은 빌드에 스택이 있으면 그게 답이다.
2. `freeDisk` 가 1GB 아래면 저장 실패와 런치 중 강제 종료를 먼저 의심한다. 앱의 잘못이 아닐 수 있지만, 저장 실패를 조용히 삼키는 곳이 있는지 본다.
3. `thermal=serious|critical` 또는 `lowPower=on` 이면 워치독(런치 20초 제한)에 걸리기 쉽다. 런치에서 메인 스레드를 붙잡는 일이 있는지 본다.
4. 사진이 **흰 화면**이면 크래시가 아니라 **멈춤**이다. 런치 중 동기 I/O, 큰 파일 디코딩, 무한 대기(세마포어 · 메인 큐 sync)를 찾는다.
5. "매번" 이고 "껐다 켜도 같다" 면 기기에 남은 **데이터**가 원인이다(손상된 파일 · 너무 큰 기록). 같은 데이터를 재현하려면 사용자에게 내보내기를 부탁한다.

**답장 틀**: 고친 버전이 나오기 전까지 할 수 있는 일(기기 재시동, 공간 비우기)을 적고, **앱을 지우지 말라**고 다시 말한다.

## 2. 느리거나 버벅여요 (`slow`)

| 묻는 것 | 부탁하는 사진 | 자동 진단 |
| --- | --- | --- |
| 어느 화면에서 얼마나 · 언제부터 | 느려지는 화면 | `[device]` |

**읽는 법**
1. 사진에서 **양**을 본다. 항목이 수백 개인 목록이면 렌더링(지연 로딩 · 계산 캐시)이 첫 의심이다.
2. "언제부터" 가 특정 업데이트를 가리키면 그 버전의 변경을 본다.
3. `memory` 가 작은 기종(3~4GB)이면 이미지 · 큰 기록 로딩이 먼저다.
4. `lowPower=on` 이면 애니메이션과 백그라운드 작업이 줄어 원래 느리게 보일 수 있다. 그 상태에서도 쓸 만한지가 기준이다.

## 3. 결제 · 구매 복원 (`purchase`)

| 묻는 것 | 부탁하는 사진 | 자동 진단 |
| --- | --- | --- |
| 무엇을 샀고 지금 어떻게 보이나 · 언제 어느 기기에서 | **구입 내역** (설정 > 이름 > 미디어 및 구입 항목 > 계정 보기 > 구입 내역) · 복원을 누른 뒤 화면 | `[purchases]` `[appReceipt]` `[storefront]` |

먼저 알림: 구입할 때 쓴 Apple 계정으로 로그인해 있는지 보라고 말한다.

**판정표** (위에서부터 맞는 줄 하나)

| 진단 | 뜻 | 할 일 |
| --- | --- | --- |
| `owned=` 에 Pro 상품이 있는데 앱이 잠겨 있음 | **앱 버그.** 권한을 받았는데 안 열었다 | 그 상품 ID 가 앱의 `entitlementIDs` 에 있는지, 권한 미러링(App Group 키)이 늦게 도는지 본다 |
| `revoked=` 에 Pro 상품 | 환불 · 취소됨 | 환불은 Apple 이 한 것이다. 사정을 설명한다 |
| `owned=none`, 구입 내역 사진에 이 앱 결제가 있음 | **다른 Apple 계정**으로 샀거나 가족 공유가 꺼졌다 | 사진의 계정과 지금 계정이 같은지 묻는다. 같다면 오퍼 코드로 보상 |
| `owned=none`, 구입 내역에 결제 없음 | 결제한 적 없다 | 결제 없이 Pro 처럼 보였던 경로(체험 · 예전 무료 혜택 · TestFlight)를 `categoryInfo` 줄로 확인하고 설명한다 |
| `firstDownload` 가 유료 앱 시절 이전 | 유료 앱으로 산 사람 | 그랜드파더 판정이 돌았는지 본다. 영수증은 Apple 계정에 묶여 있어 복원으로 돌아와야 한다 |
| `env=Sandbox` 또는 `Xcode` | TestFlight · 개발 빌드 | 거기서 본 Pro 는 App Store 판으로 넘어오지 않는다 |
| `canPay=off` | 스크린 타임이 결제를 막음 | 설정 > 스크린 타임 > 콘텐츠 및 개인정보 보호 제한을 안내한다 |
| `[purchases] timeout` | App Store 에 닿지 못함 | 네트워크 · App Store 로그인 상태를 묻는다 |

**앱이 꼭 붙여야 하는 것** (`categoryInfo`): LeeoKit 은 앱만 아는 권한(체험 · 기기에만 있는 혜택 · 무료 사용 횟수)을 모른다.
결제 분류에서 이것을 안 붙이면 "결제는 없는데 Pro 였다" 는 경우를 가릴 수 없다.

```swift
LeeoFeedbackView<MyAppSpec>(categoryInfo: { category in
    guard category == .purchase || category == .dataLoss else { return [] }
    return ["access: pro=\(isPro) grandfathered=\(isGrandfathered) trial=\(trialState) freeUse=\(freeUses)"]
})
```

**보상**: 결제가 확인됐는데 앱이 돌려주지 못하면 App Store Connect > 앱 > 오퍼 코드에서 그 상품의 일회용 코드를 만들어 답장으로 보낸다.

## 4. 동기화 · 백업 (`sync`)

| 묻는 것 | 부탁하는 사진 | 자동 진단 |
| --- | --- | --- |
| 어느 기기 사이에서 무엇이 안 맞나 · 언제부터 | iCloud 설정 화면(이 앱이 켜져 있나), 두 기기 다 | `[iCloud]` `[device]` |

**판정표**

| 진단 | 뜻 | 할 일 |
| --- | --- | --- |
| `account=noAccount` | iCloud 로그인 안 됨 | 로그인 안내 |
| `account=restricted` | 스크린 타임 · 기관 관리로 막힘 | 관리자 설정 안내 |
| `account=temporarilyUnavailable` | 계정 확인이 필요함(암호 재입력 등) | 설정 앱 맨 위의 이름을 눌러 확인하라고 안내 |
| `account=available`, 사진에 이 앱이 꺼져 있음 | 사용자가 앱별 iCloud 를 끔 | 켜는 법 안내 |
| `account=available`, 켜져 있음 | **앱 쪽을 본다** | 동기화 권한 게이트(유료 기능이면 결제 판정), 충돌 처리, 스키마가 Production 에 배포됐는지 |
| `freeDisk` 아주 적음 | 내려받기 실패 | 공간 확보 안내 |

두 기기 중 **한쪽만** 신고가 오면 다른 기기에서도 같은 분류로 하나 더 보내 달라고 한다. 두 기기의 `account` 가 다르면 대부분 그게 답이다.

## 5. 데이터가 사라졌어요 (`dataLoss`)

| 묻는 것 | 부탁하는 사진 | 자동 진단 |
| --- | --- | --- |
| 무엇이 얼마나 · **사라지기 전에 무엇을 했나** | 지금 남은 화면 + 예전 화면(있으면) | `[iCloud]` `[appReceipt]` `[device]` |

먼저 알림: 앱을 지우지 말라.

**"사라지기 전에 한 일" 이 거의 답이다**

| 그 전에 한 일 | 의심할 곳 |
| --- | --- |
| 앱 업데이트 | 그 버전의 마이그레이션. 새 형식 디코딩 실패 후 빈 배열로 덮어쓰지 않았는지(폴백 · 원본 보존) |
| 새 기기로 옮김 | 기기 이전에 안 따라오는 저장소(App Group · Keychain 접근 그룹), iCloud 복원 시점 |
| 지웠다 다시 깔기 | 기기에만 있던 데이터는 사라진다. iCloud 백업이 켜져 있었는지(`account`)와 백업 시각 |
| iCloud 를 껐다 켬 | 동기화 엔진이 "서버가 비었다" 를 "다 지워라" 로 읽지 않았는지 |
| 아무것도 안 함 | 자동 정리(보관 기간 · 개수 한도)가 사용자가 남긴 것까지 지웠는지 |

`firstDownload` 가 최근이면 이 Apple 계정으로는 **새로 받은** 앱이다. 사용자가 말하는 예전 데이터는 다른 계정이나 다른 기기에 있을 수 있다.

## 6. 알림이 안 오거나 늦어요 (`notification`)

| 묻는 것 | 부탁하는 사진 | 자동 진단 |
| --- | --- | --- |
| 어떤 알림이 언제 오기로 · 집중/무음 모드였나 | 설정 > 알림 > 이 앱 | `[notifications]` `[device]` |

**판정표**

| 진단 | 뜻 | 할 일 |
| --- | --- | --- |
| `auth=denied` | 알림을 꺼 둠 | 켜는 법 안내 |
| `auth=provisional` | 조용히 전달 중(알림 센터에만) | 배너 · 사운드를 켜도록 안내 |
| `summary=on` | **예약 요약**에 묶여 정한 시각이 아니라 요약 시각에 온다 | "늦게 와요" 의 단골. 요약에서 빼는 법 안내, 앱은 시간 민감 알림을 쓸지 검토 |
| `lockScreen=off` / `alert=off` | 와도 안 보이는 자리 | 설정 안내 |
| `timeSensitive=off` 이고 집중 모드였다 | 집중 모드가 막음 | 집중 모드에서 이 앱 허용, 앱은 시간 민감 권한 검토 |
| `pending=0` 인데 알림이 예정돼 있어야 함 | **앱 버그.** 예약이 안 됐거나 지워졌다 | 예약 코드, 64개 한도(넘치면 iOS 가 버린다), 앱 업데이트 뒤 재예약 |
| `pending` 이 64 근처 | 한도에 걸려 뒤의 것이 버려짐 | 가까운 것부터 예약하도록 |
| `lowPower=on` | 백그라운드 갱신이 줄어 원격 · 갱신형 알림이 늦음 | 로컬 예약형이면 영향 없음 |

## 7. 위젯이나 키보드가 안 돼요 (`widget`)

| 묻는 것 | 부탁하는 사진 | 자동 진단 |
| --- | --- | --- |
| 무엇이 어떻게 안 되나 · 언제부터 | 위젯이 놓인 홈 화면 / 키보드가 뜬 화면 + 설정 > 일반 > 키보드 > 키보드 | `[widgets]` `[device]` |

**위젯**
- `placed=0` 인데 위젯이 있다고 함: 다른 앱의 위젯이거나, 위젯 확장이 죽어서 등록이 빠졌다.
- 놓여 있는데 값이 멈춤: 타임라인 갱신 정책, App Group 으로 넘기는 값이 앱에서 저장된 뒤 `WidgetCenter.reloadTimelines` 를 부르는지, 위젯 확장 메모리 한도(넘치면 조용히 죽는다).
- `lowPower=on` 이면 갱신이 미뤄진다.

**키보드** (LeeoKit 이 상태를 읽을 수 없다. 앱이 `categoryInfo` 로 붙인다)
- 키보드 목록 사진에 이 앱이 없음: 추가하는 법 안내.
- 있는데 안 뜸: 키보드 확장의 메모리 한도 초과(이미지 · 큰 기록 로딩), 런치 크래시 루프(`LeeoCrashLoopGuard` 의 `launch_incomplete:keyboard` 이벤트를 허브에서 본다).
- "전체 접근 허용" 이 필요한 기능이면 사진에서 그 스위치를 본다.

## 8. 화면이나 글자가 이상해요 (`display`)

| 묻는 것 | 부탁하는 사진 | 자동 진단 |
| --- | --- | --- |
| 어느 화면의 무엇이 | 그 화면 그대로 (번역이면 고친 문장도) | `[display]` |

**읽는 법**
- `textSize` 가 `Accessibility*` 이면 큰 글씨에서 잘리는 것이다. 그 크기로 시뮬레이터를 띄워 재현한다.
- `appLang` 과 `langs` 첫째가 다르면 앱이 그 언어를 안 갖고 있어 다른 언어로 떨어진 것이다. 그 언어를 추가할지, 대체 언어가 맞는지 본다.
- `bold=on` 이면 굵은 글씨로 폭이 늘어 잘린다.
- `dark=on` 이면 다크 모드에서만 안 보이는 색(하드코딩된 흰색 · 검정)을 찾는다.
- 번역 신고는 사용자가 적어 준 문장을 그 언어 카탈로그에 그대로 반영하고, 같은 키가 다른 화면에도 쓰이는지 본다.

## 9. 그 밖의 문제 (`other`)

예전 버그 칸 그대로(언제 · 무슨 일 · 원래는) 묻고, `[device]` 만 붙인다.
이 분류로 같은 종류의 신고가 쌓이면 **새 분류를 만들 신호**다.

## 앱에서 켜는 법

분류는 따로 켜지 않아도 버그 신고에 뜬다. 보여 줄 분류는 Spec 에서 고른다(`LeeoBugCategory.defaults`).

- 결제 분류: 파는 것이 있을 때만 (`Spec.paywall != nil`).
- 동기화 · 알림 · 위젯 분류: `capabilities` 에서 `.cloudSync` · `.pushNotifications` · `.widgets` 를 **해당 없음**으로 선언한 앱에서만 빠진다. 선언하지 않았으면 보인다.
- 직접 고르려면 `LeeoFeedbackView(bugCategories: [...])`, 분류를 아예 안 물으려면 `bugCategories: []`.

**사진을 받으려면** `LeeoFeedbackConfig(acceptsScreenshots: true)` 와 Dashboard 의 `screenshot1~3` (Asset) 필드 배포가 필요하다.
꺼 두면 분류의 사진 안내도 보이지 않는다. 결제 분류는 **구입 내역 사진이 판정의 절반**이라 켜 두는 것을 권한다.

## 진단이 읽지 않는 것

- 사용자가 쓴 내용(단축어 본문, 메모, 일정)은 읽지 않는다.
- Apple 계정 이메일, 결제 수단, 영수증 금액은 읽지 않는다(애초에 읽을 수 없다). 그래서 구입 내역 사진을 부탁한다.
- 백그라운드 앱 새로고침 상태는 앱 익스텐션에서 읽을 수 없어 빠졌다. 필요한 앱은 `extraInfo` 로 붙인다.
